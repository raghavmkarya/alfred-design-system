Design system notes

Adopting this

What the Alfred design system would take from the terminal aesthetic, and where the costume stops fitting a premium executive brand.

What we would add

  • A mono token layer: --font-mono (JetBrains Mono or Geist Mono, both free) for data, evidence trails, model reasoning, keyboard hints and API surfaces. Monospace reads as rigor, which suits decision intelligence.
  • A console-style evidence panel: one dark surface with 1px hairline borders where Alfred shows its reasoning as prompt-prefixed lines with a blinking cursor. It fits the dark marketing site natively.
  • Keyboard-first affordances: kbd keycap tokens, "press / to ask Alfred", and a command-palette motif. Chief-of-staff behaviour with no retro dress.
  • Recolored phosphor: orange #FF8431 plays the amber role (glow: 0 0 6px rgba(255,132,49,.35)) and periwinkle #A7A7FC takes the cool role. Never import green #33FF66 or amber #FFB000 as tokens.
  • In moderation: hairline borders, denser tables and a single grain-texture surface, kept to the app's evidence and detail zones.

What clashes with the brand

  • Sharp 0px corners and hard offset shadows contradict Alfred's soft 12/24/32px radii and diffuse vertical shadows. If a console panel wants sharper edges, floor it at 12px.
  • ASCII ornament, traffic-light window chrome, scanlines and flicker are hobbyist, ironic signals that undercut a premium executive brand. Skip them.
  • Mono-everything typography and green-on-black would read as a different company. Clash Display owns headlines, and the Tailscale lesson holds: dev credibility comes from structure and precision, not costume.
